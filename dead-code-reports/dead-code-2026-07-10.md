## Methodology note — adapted for the concatenation model

As established in the 2026-06-26 report, this codebase does **not** fit the
standard "named export never imported" model. Only **six** files are true ES
modules with `import`/`export` syntax:

- `src/js/logger.js`
- `src/js/pure-fns.js` (barrel, re-exports only)
- `src/js/pure-fns-format.js`
- `src/js/pure-fns-validate.js`
- `src/js/pure-fns-tasks.js`
- `src/js/pure-fns-export.js`

The remaining **43** `src/js/*.js` files (`00-config.js` … `25-rollingsummary.js`,
excluding `00-config.local.example.js` which is excluded from the build and
contains no declarations) are `sourceType: 'script'` files with no `import`/
`export` syntax at all. `build.js` concatenates them alphabetically into a
single IIFE-style module (`script.js`), and they call each other's top-level
`function`/`const`/`class`/`let` declarations through a shared global scope.
`build-portable.js` does the same for the portable/offline build, additionally
stripping ESM syntax from the six leaf modules and inlining them first
(`LEAF_MODULES` in `build-config.js`).

Because of this, cross-file "import site" grepping is meaningless for the 43
script files — a lint tool like `no-unused-vars` cannot see cross-file calls
in a concatenation build either. This report reuses the same signal as the
2026-06-26 and 2026-06-23 sweeps:

- A top-level `function` / `const` / `let` / `class` declaration is a **dead
  top-level symbol** when its whole-word text appears **≤ 1 time** (its own
  declaration line, zero calls/references) across the full analysis scope.
- For the six true ES modules, named exports were additionally verified by
  the same whole-word signal, cross-checked against `build-config.js`'s
  `readPureFnsExports()` (which reads `pure-fns.js`'s re-export statements and
  injects them as a single `import { … } from './src/js/pure-fns.js';` line at
  the top of the concatenated `script.js` — this is how the 43 script files
  "consume" pure-fns/logger exports without any per-file `import` statement).

**Scope for whole-word reference counting:** all 49 `src/js/*.js` files,
`work-log.html`, `build.js`, `build-config.js`, `build-portable.js`,
`smoke-tests.cjs`, and `test/unit.mjs` (the repo has no `test/unit.cjs` —
the actual unit-test file is `test/unit.mjs`, which loads the concatenated
script files into `vm.runInContext` sandboxes to exercise their top-level
functions as classic scripts).

- Top-level symbols analysed: **477** (438 across the 43 concatenated script
  files + 35 named exports across the four `pure-fns-*.js` sub-modules +
  `wlLog` from `logger.js`; the `pure-fns.js` barrel itself declares no
  symbols, only re-export statements)
- Symbols with reference count ≤ 1 (dead): **0**

No dynamic `import(...)` calls exist anywhere in `src/js/`, `build.js`,
`build-portable.js`, or `build-config.js`, so the "possibly used (dynamic
import)" category is empty by inspection, not by omission.
