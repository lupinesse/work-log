## Methodology notes

- **Analysis date:** 2026-09-18
- **Scope:** `src/js/*.js` (62 files, ~15,950 lines) + `build.js` +
  `build-portable.js` + `build-config.js` + `smoke-tests.cjs` +
  `work-log.html` + `test/unit/*.test.mjs` (35 test files). This repo has no
  `test/unit.cjs` file (the path named in the skill's generic template) —
  tests live under `test/unit/*.test.mjs`, so that directory was used
  instead.

- **Build architecture matters here.** Only 15 files are true ES modules with
  `export` statements: `app-constants.js`, `logger.js`, `date-labels.js`,
  `signifiers.js`, `12b-changelog-data.js`, `pure-fns.js`, and the nine
  `pure-fns-*.js` sub-modules it re-exports as a barrel. These are
  `LEAF_MODULES` (`build-config.js`) — `build.js` generates an `import { ... }`
  line pulling in *every* export `readModuleExports()` finds in each leaf, so
  a leaf export is "consumed by the build" automatically regardless of
  whether anything actually uses it afterwards. The remaining 47 files have no
  `import`/`export` syntax at all — `build.js` concatenates them
  alphabetically into one global-scope script. A "dead export" check for the
  15 leaf files therefore has to mean "never referenced by *name* anywhere
  else in the concatenated app or its tests," not "never explicitly
  imported" — plain identifier references from the global-scope files are the
  real usage signal. That's what the numbers in this report measure.

- **`pure-fns.js` barrel re-exports don't count as usage.** Every symbol in
  the nine `pure-fns-*.js` sub-modules is re-exported wholesale by
  `pure-fns.js` (`export { foo, bar, ... } from './pure-fns-x.js'`), so a
  naive grep for a symbol name would always find at least one hit there even
  if nothing ever calls it. The cross-reference script only counted a
  declaring file's own single-line `export function/const/class` statements
  as "exports to check" — the multi-line `export { ... } from` barrel blocks
  in `pure-fns.js` were not treated as separate declarations, so a symbol
  only reachable through the barrel and never actually called would still
  have shown up as dead against its true declaring file. None did.

- **Unused-local-function check needed a second pass.** The skill's Step 4
  as written checks only for same-file calls. Because most `src/js/*.js`
  files are concatenated into one global scope (not real ES modules), a
  same-file-only, call-syntax-only (`fnName(`) check flags dozens of
  functions that are genuinely called from *other* concatenated files or
  wired up as bare function references — e.g. `resetPomo`, `openRapid`,
  `toggleViewLocation`, `openWeeklyReportOverlay`, `copyWeeklyReportText`,
  `openSprintSetup`, `showSprintReview`, `renderRow` are all passed via
  `element.addEventListener('click', fnName)` or `.map(fnName)` (a bare
  identifier reference, not a `fnName(` call). An initial same-file,
  call-syntax pass produced 18 candidates; a whole-codebase check for the
  bare identifier (word-boundary match, not just `name(` call syntax) found a
  real reference for every one of them. One further apparent candidate,
  `qpHidden` in `01-state.js`, is a `const` holding a `Set` built from an
  IIFE, not a function — it's actively read/written from
  `04d-render-quickpick.js` and `05a-export.js`.
