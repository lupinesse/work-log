## Methodology note — adapted for the concatenation model

The standard "named export never imported" analysis does not fit this codebase:
`src/js/*.js` are `sourceType: 'script'` modules concatenated into a single
browser IIFE at build time, so they do **not** use `import`/`export` — they call
each other through a shared global scope (only `logger.js` and `pure-fns*.js` are
true ES modules). This is why genuinely-dead top-level symbols are invisible to lint
(`no-undef` / `no-unused-vars` cannot see cross-file calls in concatenated builds).

This report uses the same reference-count signal as the previous sweep: a top-level
`function` / `const` / `let` / `class` is **dead** when the whole-word symbol
appears ≤ 1 time (its own definition, no references) across the entire analysis scope.

## Methodology notes
- Analysis date: 2026-06-26
- Scope: `src/js/*.js` + `work-log.html` + `build.js` + `build-config.js` + `build-portable.js` + `smoke-tests.cjs` + `test/unit.mjs`
- Signal: whole-word reference count across the scope above; symbols with ref count ≤ 1 (definition only, no calls) are dead candidates, each verified manually
- Generated docs (`docs/*.html`) and build artefacts (`script.js`, `dist/`) are excluded — they are derived from source, not references
- Pure-fns exports are consumed by the build pipeline via `readPureFnsExports()` in `build-config.js`, which injects them as named imports in `script.js`; each was additionally verified to have at least one call site in the concatenated source files
