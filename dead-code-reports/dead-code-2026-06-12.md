## Methodology notes

- Analysis date: 2026-06-12
- Scope: `src/js/*.js` + `build.js` + `build-portable.js` + `smoke-tests.cjs` + `test/unit.mjs`
- Build model: `build.js` concatenates all `src/js/*.js` files (alphabetically,
  excluding LEAF_MODULES) into `script.js`. LEAF_MODULES (`logger.js`,
  `pure-fns.js`) are imported via ES `import` at the top of `script.js`.
  `readPureFnsExports()` in `build-config.js` dynamically reads every named
  export from `pure-fns.js` and includes them all in the generated import
  statement — so all 33 exports are in scope throughout the concatenated build.
- All 33 named exports from `pure-fns.js` and the single export (`wlLog`) from
  `logger.js` were cross-referenced against all other source files, build
  scripts, smoke tests, and unit tests.
- `build-config.js` exports (`JS_SRC`, `CSS_SRC`, `JS_OUT`, `CSS_OUT`,
  `HTML_IN`, `PORTABLE_OUT`, `PS_SERVER`, `PS_CONFIG`, `BACKUPS_DIR`,
  `DEST_FILE`, `LEAF_MODULES`, `readPureFnsExports`) are consumed exclusively
  by Node.js build scripts and are out of scope for browser-code dead-export
  analysis.
- Dynamic imports: none found; all `import(...)` patterns were checked.
- Default exports: neither leaf module uses `export default`; no default-export
  analysis required.
