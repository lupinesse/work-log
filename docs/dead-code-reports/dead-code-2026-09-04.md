## Methodology notes — adapted for the concatenation model

Only **nine** files are true ES modules with `import`/`export` syntax:
`app-constants.js`, `logger.js`, `date-labels.js`, `pure-fns.js` (barrel),
`pure-fns-format.js`, `pure-fns-validate.js`, `pure-fns-tasks.js`,
`pure-fns-export.js`, and `pure-fns-epics.js` (new since 2026-08-14). The
remaining **49** `src/js/*.js` files have no `import`/`export` syntax at
all — `build.js` concatenates them alphabetically into a single script
(`script.js`), and they call each other's top-level declarations through a
shared global scope. `build-portable.js` does the same for the portable
build, additionally stripping ESM syntax from the nine leaf modules and
inlining them ahead of the concatenated body.

Because cross-file "import site" grepping (as in Step 1/3 of the standard
methodology) would be meaningless for the 49 concatenated script files, this
report follows the same adapted approach as every prior sweep: a whole-word
reference-count signal. A symbol is a **dead candidate** when its whole-word
occurrence count across the full analysis scope does not exceed its own
"definitional" mentions (its own declaration line for non-leaf/simple leaf
exports; declaration line **plus** one `pure-fns.js` barrel re-export mention
for the five barrelled sub-modules).
