## Methodology notes — adapted for the concatenation model

Only **six** files are true ES modules with `import`/`export` syntax:
`logger.js`, `pure-fns.js` (barrel), `pure-fns-format.js`,
`pure-fns-validate.js`, `pure-fns-tasks.js`, `pure-fns-export.js`. The
remaining **45** `src/js/*.js` files (`00-config.js` … `25-rollingsummary.js`,
excluding `00-config.local.example.js`, which contains no declarations and is
excluded from the build) have no `import`/`export` syntax. `build.js`
concatenates them alphabetically into a single script (`script.js`), and they
call each other's top-level declarations through a shared global scope.
`build-portable.js` does the same for the portable build, additionally
stripping ESM syntax from the six leaf modules and inlining them.

Because cross-file "import site" grepping is meaningless for the 45 concatenated
script files, this report uses a whole-word reference-count signal: a top-level
`function`/`const`/`let`/`class` is a **dead symbol** when its whole-word text
appears ≤ 1 time (its own declaration line only) across the full analysis scope.

- Scope: all 51 files in `src/js/*.js` (52 total, excluding
  `00-config.local.example.js`), `work-log.html`, `build.js`,
