## Dead exports

None. The codebase has only **six** true ES modules with `import`/`export`
syntax: `logger.js` and the `pure-fns.js` barrel over its four leaf
sub-modules (`pure-fns-format.js`, `pure-fns-validate.js`,
`pure-fns-tasks.js`, `pure-fns-export.js`). The remaining 45 `src/js/*.js`
files (`00-config.js` … `25-rollingsummary.js`, excluding
`00-config.local.example.js`, which contains no declarations and is excluded
from the build) have no `import`/`export` syntax at all — `build.js`
concatenates them alphabetically into `script.js`, where they share a single
global scope.

All 36 leaf-module symbols (`wlLog` plus 35 across the four `pure-fns-*.js`
sub-modules) were checked with whole-word grep against every other file in
scope:
- `wlLog` — called 100+ times across the 45 concatenated files, plus in
  `build.js`, `vite.config.js`, `work-log.html`, and 47 times in
  `test/unit.mjs`.
- Every `pure-fns-format.js` / `pure-fns-validate.js` / `pure-fns-tasks.js` /
  `pure-fns-export.js` symbol is consumed both via the `pure-fns.js` barrel
  (re-exported, then injected into `script.js`'s top `import` line by
  `readPureFnsExports()` in `build-config.js`) **and** has a direct call site
  in at least one concatenated production file (e.g. `dk` in 30+ files,
  `validEntry` in `01-state.js`/`05a-export.js`, `WORK_LOCATIONS`/
  `locationFor`/`nextLocation` in `24-location.js`/`25-rollingsummary.js`).
- `test/unit.mjs` additionally does `import * as pureFns from
  '../src/js/pure-fns.js'`, so every barrel symbol also has a namespaced
  test reference — but none rely on tests alone; all have production
  call sites too.

No `<file>:default` exports exist anywhere in `src/js/` (only
`commitlint.config.js`, `eslint.config.js`, and `vite.config.js` — outside
the analysis scope — use `export default`).

## Methodology notes

- Analysis date: 2026-08-07.
- Scope: all 51 non-example files in `src/js/*.js`, plus `build.js`,
  `build-portable.js`, `build-config.js`, `deploy-portable.js`,
  `vite.config.js`, `smoke-tests.cjs`, `test/unit.mjs`,
  `scripts/config-snapshot.cjs`, and `work-log.html`.
- Confirmed via `git log --since=2026-07-31 -- src/js/ build.js
  build-portable.js` that 14 feature/fix PRs (#275–#306) landed since the
  last report, so this sweep is a genuine fresh analysis, not a rubber-stamp
  of 2026-07-31's result.
- Named-export cross-referencing used whole-word regex matching (negative
  lookaround on `\w`/`$`) to avoid substring false-positives (e.g. `fmtDur`
  vs `fmtDurLong`, `dk` vs a hypothetical `dks`), applied programmatically
  across every file pair rather than by eye.
- Local-function analysis first found candidates with zero within-file
  references (the literal Step 4 signal), then verified each one against
  the full corpus before drawing any conclusion — the concatenation
  architecture (noted in Step 2 of the procedure) makes an in-file-only
  check alone unreliable, since cross-file calls via global scope are the
  normal calling convention for the 45 non-leaf files.
- No default exports exist in `src/js/`, so the default-export cross-check
  (against `build.js`/`build-portable.js` concatenation) had nothing to
  verify.
- Corroborates every prior sweep back to 2026-06-23 — the project has
  stayed free of dead exports and dead local functions through 14 rounds
  of feature work.
