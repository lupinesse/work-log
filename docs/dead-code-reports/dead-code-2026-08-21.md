## Unused local functions
| File | Function | Lines |
|---|---|---|
| `src/js/05b-filesystem.js` | `clearDirHandle` | L77–87 (11 lines) |
| `src/js/05b-filesystem.js` | `pickSaveFolder` | L137–152 (16 lines) |

Both are `async function` declarations, not exported, with no call site
anywhere in `src/js/`, `work-log.html`, `build.js`, `build-portable.js`,
`smoke-tests.cjs`, or `test/unit/*.test.mjs`. Confirmed dead:

- **`clearDirHandle`** — would clear the persisted File System Access
  directory handle from IndexedDB. There is no UI control or other function
  in the codebase that calls it, so a user can never revoke a chosen save
  folder short of clearing site data manually.
- **`pickSaveFolder`** — would prompt the user to choose a save folder via
  `window.showDirectoryPicker`. `renderFolderStatus()` renders a
  `#folderStatus` element that *describes* "pick save folder" as clickable
  behaviour, but nothing in `src/js/` or `work-log.html` wires a click
  handler (or any other call) to this function — the described interaction
  does not exist in the shipped code. This looks like a UI affordance that
  lost its event binding, not intentionally-unused code — worth a human
  second look before deletion, since deleting it fixes the symptom (dead
  code) but not the underlying gap (no way to invoke folder selection).

All other candidates surfaced by an initial per-file "called only within its
own file" pass turned out to be false positives — see Methodology notes.

## Methodology notes
- Analysis date: 2026-08-21
- Scope: `src/js/*.js` (54 files with content, `00-config.local.example.js`
  excluded — it has no exports or functions and is excluded from every build
  by name) + `build.js` + `build-portable.js` + `build-config.js` +
  `smoke-tests.cjs`. **No `test/unit.cjs` exists in this repository.** The
  test suite lives at `test/unit/*.test.mjs` (26 files); those were used as
  the "test files" cross-reference target for Steps 3 and 4 instead.
- Dynamic imports: none exist in this codebase (checked, see above), so the
  "possibly used" category is empty rather than skipped.
- Default exports: none exist in this codebase — `grep -rn "export default"
  src/js/*.js` returns nothing. Step 3's default-export handling is
  therefore not applicable.
- **Architecture-driven correction to Step 4.** This codebase is not a pure
  ES-module graph. Per `build-config.js`/`build.js`, only 8 files are true
  leaf ES modules imported with `import`/`export` syntax: `app-constants.js`,
  `logger.js`, `pure-fns-export.js`, `pure-fns-format.js`,
  `pure-fns-tasks.js`, `pure-fns-validate.js`, `pure-fns.js` (a re-export
  barrel over the four `pure-fns-*.js` files), and `date-labels.js`. All other
  45 numbered files (`00-config.js` … `25-rollingsummary.js`) have **zero**
  `export` statements and are concatenated verbatim into `script.js` in
  alphabetical order, sharing one flat module scope — a function declared
  without `export` in `07-lifecycle.js` is called directly by name from
  `16-rapid.js` at runtime, with no import required.
  Running Step 4 literally as specified ("never called *within the same
  file*") against this architecture produced 58 candidates, but a follow-up
  whole-repo cross-check showed 56 of them are called from *other*
  concatenated files (e.g. `initRapid()`, `initMigration()`, `initTrackers()`,
  `initSprints()`, `initLocation()` are all invoked from the startup sequence
  in `07-lifecycle.js`, not from within their own defining file). Reporting
  those 56 as dead would have been false positives dangerous to an automated
  removal pass, so this report applies a **whole-`src/js/`-corpus check**
  (plus `build.js`/`build-portable.js`/`smoke-tests.cjs`/tests) instead of a
  strictly per-file one for local-function usage, and only the 2 functions
  with genuinely zero references anywhere in the repository are listed above.
- Every exported symbol from the 8 leaf modules (61 total) was grepped
  individually as a whole word across every other `src/js/*.js` file,
  `build.js`, `build-portable.js`, `build-config.js`, `smoke-tests.cjs`, and
  all 26 `test/unit/*.test.mjs` files. References appearing only inside
  `pure-fns.js`'s own `export { … } from '...'` barrel lines were treated as
  a mechanical pass-through, not real usage, when classifying test-only
  exports (both flagged symbols are re-exported by the barrel but never
  called from any file other than their own declaring module and the test
  suite).
- If everything had been used, that would have been stated explicitly;
  instead this report found 2 test-only exports (informational, not a
  removal candidate) and 2 genuinely dead local functions (real removal
  candidates, `src/js/05b-filesystem.js`).
