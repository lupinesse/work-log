## Test-only exports

Only six files in `src/js/` are true ES modules with `import`/`export`
syntax: `logger.js`, `pure-fns.js` (barrel, re-exports only), and its four
leaf sub-modules `pure-fns-format.js`, `pure-fns-validate.js`,
`pure-fns-tasks.js`, `pure-fns-export.js`. The remaining 43 `src/js/*.js`
files (`00-config.js` … `25-rollingsummary.js`) have no `import`/`export`
statements at all — `build.js`/`build-portable.js` concatenate them
alphabetically into one script scope, and they call each other's top-level
declarations as shared globals. `00-config.local.example.js` is excluded
from the build and declares no reassignable state.

Of the 35 named exports declared across the four `pure-fns-*.js` leaf
modules (all re-exported through the `pure-fns.js` barrel), 33 have at least
one direct call site in a concatenated `src/js/*.js` file outside their own
declaring file. Two do not:

| File | Symbol | Used in |
|---|---|---|
| `src/js/pure-fns-export.js` | `stripJiraPrefix` | `test/unit.mjs` (`describe('stripJiraPrefix', …)`) — plus one internal call from `buildBillableSummaryParts` in the *same* file |
| `src/js/pure-fns-export.js` | `applyBackupRetention` | `test/unit.mjs` (`describe('applyBackupRetention', …)`) — plus one internal call from `buildBackupPayload` in the *same* file |

Both are exported (and re-exported through the `pure-fns.js` barrel, so
`build.js`'s `readPureFnsExports()` still pulls them into `script.js`'s
global scope), but no file outside `pure-fns-export.js` calls either one
directly — every production caller goes through the higher-level function
that wraps it (`buildBillableSummaryParts` wraps `stripJiraPrefix`;
`buildBackupPayload` wraps `applyBackupRetention`). This is a real change
since the 2026-06-26 sweep: at that time `applyBackupRetention` was called
directly from `05a-export.js`'s `exportBackup()`; that call site was removed
when `buildBackupPayload()` was extracted as its own tested pure function
(landed as commit #255, per the 2026-07-10 report), leaving
`applyBackupRetention` reachable only through `buildBackupPayload` and the
test suite.

Neither function is dead — both still run in production via their wrapper —
but neither needs its own top-level export any more; they could be
un-exported (kept as unexported helpers within `pure-fns-export.js`, still
reachable by `test/unit.mjs` via the module's other exported entry points'
behavior, or tested indirectly through `buildBillableSummaryParts` /
`buildBackupPayload`) without changing any runtime behavior. Flagged as
test-only rather than dead because the test suite exercises them directly
via `import * as pureFns from '../src/js/pure-fns.js'`.

## Methodology notes
- Analysis date: 2026-07-24
- Scope: `src/js/*.js` (49 files, all read in full) + `build.js` +
  `build-portable.js` + `smoke-tests.cjs` + `test/unit.mjs` (this repo has
  no `test/unit.cjs`; the actual unit-test file is `test/unit.mjs`)
- Dynamic imports: none exist in this codebase (confirmed by direct grep of
  `import(`, not assumed absent)
- Default exports: none exist anywhere in `src/js/` (`grep -rn "export default"`
  returns no matches), so the "possibly dead default export" check has no
  candidates to cross-check against `build.js` concatenation order
- Named exports: cross-referenced by exact whole-word grep against every
  other `src/js/*.js` file, `build.js`, `build-portable.js`,
  `smoke-tests.cjs`, and `test/unit.mjs`; a reference inside the same
  declaring file (e.g. one exported pure function calling a sibling exported
  pure function in the same file) does **not** by itself clear a symbol of
  the "test-only" label if no *other* file also calls it directly — see
  `stripJiraPrefix` / `applyBackupRetention` above
- Local (non-exported) functions: because the 43 concatenated script files
  share one global scope by design (not ES modules), a same-file-only call
  check would produce false positives for the many render/init functions
  that are deliberately defined in one file and invoked from another
  (e.g. `renderPlan` in `10a-tasks-render.js`, called from
  `07-lifecycle.js`, `10b-tasks-events.js`, `10c-tasks-board.js`, etc.).
  This report therefore checked call sites across the **entire** `src/js/`
  tree (plus `work-log.html`, `smoke-tests.cjs`, `test/unit.mjs`) rather than
  literally restricting the search to each function's own file, and treated
  reference-style usage (a bare function name passed to `addEventListener`,
  `.map()`, or an object literal, with no trailing `(`) as a real call site
