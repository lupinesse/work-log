## Observations

### `05b-filesystem.js` — 5 dead exports, `#folderStatus` absent from HTML
`openIDB`, `getSavedDir`, `storeDirHandle`, `clearDirHandle`, and
`pickSaveFolder` are all internal implementation helpers for `writeExportFile`
and `renderFolderStatus`. They were likely exported speculatively or when the
FSA feature was first wired up. None is consumed by any other module. The
`#folderStatus` element they depend on is absent from `work-log.html`, meaning
`renderFolderStatus()` is a no-op at runtime and `clearDirHandle` is never
invoked at all. Consider whether the folder-save UI is intended to be hidden or
whether the element was accidentally dropped.

### `01b-migrate.js` — 3 self-invoking exports
`migrateStorage`, `migrateEntryDatesToLocal`, and `removeRetiredKeys` are
called at module level as side effects. Exporting them adds no value unless
a caller or test needs to invoke them on demand; consider removing the `export`
keyword (the side-effect calls at lines 148-150 are unaffected).

### Pure-function sub-modules — 4 private helpers over-exported
`epicCutoffDate`, `collectRecentlyUsedCatIds` (both in `pure-fns-epics.js`),
`applyBackupRetention` (`pure-fns-backup.js`), and `buildTimesheetDescription`
(`pure-fns-hours-entry.js`) are internal helpers that support their module's
own public API. The `pure-fns.js` barrel re-exports them, making them part
of the public surface even though nothing outside each file uses them directly.
Removing their `export` declarations and their entries in `pure-fns.js` would
not change any observable behaviour.

### `01c-save.js`, `24-location.js`, `25-rollingsummary.js`, `12d-weeklyreport.js` — helper functions not needed at module boundary
The remaining 8 dead exports follow the same pattern: an exported helper that
is only called from within the same module. Removing the `export` keyword
keeps the function available locally while reducing the public API surface.
