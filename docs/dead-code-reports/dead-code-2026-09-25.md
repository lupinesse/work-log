## Methodology notes

- **Analysis date:** 2026-09-25
- **Scope:** `src/js/*.js` (63 files) + `build.js` + `build-portable.js` +
  `build-config.js` + `vite.config.js` + `smoke-tests.cjs` +
  `work-log.html` + `test/unit/*.test.mjs` (35 test files). This repo has no
  `test/unit.cjs` file (the path named in the skill's generic template) —
  tests live under `test/unit/*.test.mjs`, so that directory was used
  instead, as in prior sweeps.

- **Build architecture matters here.** Only 15 files are true ES modules with
  `export` statements — `app-constants.js`, `logger.js`, `date-labels.js`,
  `signifiers.js`, `12b-changelog-data.js`, `pure-fns.js`, and the nine
  `pure-fns-*.js` sub-modules it re-exports as a barrel. These are the
  `LEAF_MODULES` (`build-config.js`); `build.js`/`build-portable.js`/
  `vite.config.js` all generate an `import { ... }` line pulling in every
  export `readModuleExports()` finds in each leaf. The remaining 48 files
  (including `00-config.local.example.js`, which is a fully-commented
  template intentionally excluded from the build by an `.example.js` filter)
  have no `import`/`export` syntax at all — the build reads them via
  `readdirSync`, sorts alphabetically, and concatenates them into one
  global-scope module body. A "dead export" check for the 15 leaf files
  therefore has to mean "never referenced by *name* anywhere else in the
  concatenated app or its tests," not "never explicitly imported" — plain
  identifier references from the global-scope files are the real usage
  signal. That's what the numbers in this report measure.

- **`pure-fns.js` barrel re-exports don't count as usage on their own.**
  Every symbol in the nine `pure-fns-*.js` sub-modules is re-exported
  wholesale by `pure-fns.js` (`export { foo, bar, ... } from
  './pure-fns-x.js'`), so a naive grep for a symbol name always finds at
  least one hit there even if nothing ever calls it. Consumer lists above
  and in the underlying analysis treat that barrel line as a structural
  artefact, not evidence of use, and look for a real call site elsewhere.
  None of the 80 leaf-module symbols relies on the barrel line as its only
  reference.

- **Unused-local-function check needed a second pass.** The skill's Step 4
  as written checks only for same-file calls. Because most `src/js/*.js`
  files are concatenated into one global scope (not real ES modules), a
  same-file-only check flags functions that are genuinely called from
  *other* concatenated files or wired up as bare function references (e.g.
  `element.addEventListener('click', fnName)`, `.map(fnName)`) rather than a
  `fnName(...)` call syntax. The initial same-file pass produced 45
  candidates across 22 files (e.g. `initBannerControls`,
  `bindPlanEvents`, `checkBlockNotifications`, `initLocation`,
  `renderRollingSummary`); a follow-up whole-codebase check for each bare
  identifier found a real reference for every one of them in a sibling
  `src/js` file.

- No source files were modified — this report is informational only.
