2. **Reduce single-letter lambda vars** — 431 instances of single-letter arguments in `.map()`, `.find()`, `.filter()`, `.reduce()` chains throughout `src/js/`. PR #217 addressed catch blocks (`err`), but the callback pattern (`(e) =>`, `(t) =>`, `(d) =>`) was untouched. Rename in high-traffic files first: `10c-tasks-board.js`, `07-lifecycle.js`.

3. **Split `04-render.js` (686 lines) and `09-clock-weather.js` (608 lines)** — the module-size split programme reduced the biggest offenders well (e.g. `10b-tasks-events.js` 883 → 362, `pure-fns.js` split into 4 sub-modules), but `04-render.js` and `09-clock-weather.js` remain large monoliths with mixed concerns. Even a theme-based split to `04a-`/`09a-` sub-modules would help.

4. **Align `.nvmrc` with `engines` in `package.json`** — `.nvmrc` pins `24.15.0`; `package.json` `engines` says `>=22.12.0`. Either bump `engines` lower bound to `>=24` (if Node 24 features are actually used) or relax `.nvmrc` to a comment. Small fix, eliminates silent confusion for new contributors.

5. **Verify JSDoc generates cleanly** — `jsdoc` is not installed in this audit environment, so the effect of #213 could not be confirmed by running `npm run docs`. Add a CI step to `docs.yml` (or a standalone job) that fails the build when `npm run docs` exits non-zero, so parse errors cannot regress silently again.
