## Priorities for this week

1. **Merge PR #367 — it fixes a live, 9-to-14-day-old CI outage.** `scss-audit.yml` and
   `dead-code.yml` have been failing on every run since 2026-08-15 and 2026-08-10/17 respectively,
   for the reason described in Regressions above (credential order + a `bash -e` abort that sealed
   the CLI's only diagnostic in an unread file). #367 is **already open, CI-green (8/8 checks
   pass), non-draft, `mergeable_state: clean`, and has sat unreviewed for 3 days** (opened
   2026-08-21T14:24, still open as of this review). It fixes the credential order in both files,
   captures the exit status explicitly instead of letting `bash -e` abort, prints the CLI output on
   the failure path via a collapsible `::group::`, uploads the raw output as a build artifact, and
   — notably — adds `lib/claude-cli-workflow-guards.mjs` plus a test suite that runs the same three
   checks (don't discard the OAuth token; survive a non-zero exit if output is captured; actually
   print what's captured) against **every** workflow in `.github/workflows/`, not just the two that
   broke, so a fourth `claude -p` workflow can't repeat this silently. This is the single
   highest-value action available this week — it's already done, tested, and just needs a merge.

2. **`auto-fix-ci.yml`'s "Find PR number" step hard-crashes on a real PR CI failure — new finding,
   not covered by #367.** `gh api "repos/.../actions/runs/<id>/pulls"` returned HTTP 404 when this
   step actually ran against a genuine PR-branch CI failure (job `96722486793`, 2026-08-21). Under
   the job's default `bash -e`, that 404 aborts the whole step with a bare exit-code-1 instead of
   falling through to the intended "no PR found, skip" path — so the one time this workflow is
   supposed to matter (a real CI failure on a PR), it currently fails silently instead of posting
   its diagnosis comment. Every other trigger this review found (20 in the last week) hit the
   job-level `if:` guard and skipped before reaching this step, which is why the bug hasn't shown
   up before. Fix: wrap the `gh api` call so a non-2xx response degrades to `found=false` rather
   than aborting the step, and add it as a fourth case to `claude-cli-workflow-guards.mjs` or a
   dedicated regression test, the same way #367 is guarding the other two workflows.

3. **`QA.md`'s test-count table is stale for a sixth consecutive review, and `ARCHITECTURE.md`'s
   refresh is already stale again within days of landing.** `QA.md` still reads 647 unit / 99
   suites / 1,215 total; actual is **669 / 104 / 1,278** (669 unit + 320 smoke + 289 CI-script).
   `ARCHITECTURE.md` was refreshed in #361 (2026-08-17, cert bumped to `1.9.2-r3`) and correctly
   shows 669 unit tests — but its CI-script line still reads 276 (56 suites); actual is now **289

   "refreshed, stale again within a day or two" pattern flagged for three straight reviews now.
   Folding the count refresh into the release-cut or PR-merge checklist (rather than a
   QA-triggered fix every week) remains the recommendation, repeated for the sixth time.

4. **Node-version story still unreconciled, second review running.** `.nvmrc`/`engines.node`
   (`22.22.1`, lowered in #353) still don't match what `ci.yml`/`.devcontainer/devcontainer.json`
   actually test (Node `24` only) — unchanged since last review flagged it. No PR this week
   touched either side of the gap. Either add a Node-22 job to `ci.yml`, or raise the documented
   floor back to 24.

5. **Six PRs are open and waiting, several CI-green for 3+ days.** #367 (Priority 1, ready), #365
   ("archive stale epics," CI-green apart from the repo-wide `scss-audit` outage, open since
   2026-08-21), #368 ("session guard," CI-green, open since 2026-08-21), #366 (dead-code sweep,
