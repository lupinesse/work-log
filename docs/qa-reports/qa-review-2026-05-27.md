## Priorities for this week

1. **Fix JSDoc type-expression syntax in `00-pure-fns.js` and `10-tasks.js`** —
   Replace TypeScript optional notation (`error?: string`, `priority?: number`) with
   valid JSDoc alternatives (`{string|undefined}` or remove the `?`). This stops
   `npm run docs` from emitting 8 errors and ensures all parameter types appear in
   the generated HTML. Affects 2 files, ~10 lines. Small, high-impact fix.

2. **Tag v1.8.1–v1.8.3 in git history** — Three changelog entries have no
   corresponding git tag. Identify the merge commits for each and run
   `git tag -a v1.8.x -m "Release v1.8.x" <sha>`. The `release.yml` workflow
   and reproducibility requirement both depend on every release being findable
   by tag.

3. **Document branching strategy and install commitlint (issue #11)** — Add a
   "Branching" section to `CONTRIBUTING.md` (feature branches, squash-merge to
   main). Add `commitlint` with `@commitlint/config-conventional` to the Husky
   `commit-msg` hook. Currently 7/20 recent commits bypass the conventional-commit
   format; the CI has no enforcement.

4. **Split `10-tasks.js` into rendering and logic modules (issue #8)** — At
   1 255 lines it violates the single-reason-to-change rule. Extract task
   DOM-rendering functions to `10a-tasks-render.js` and keep mutation/state
   logic in `10-tasks.js`. This also unblocks cleaner unit tests.

5. **Add branch-decision logging to BuJo modules (issue #12)** — `18-dailylog.js`,
   `19-monthlylog.js`, `21-reflection.js` do not call `wlLog` when skipping,
   finding no data, or choosing rendering paths. Add `wlLog.info()` calls at key
   decision points to match the logging standard set by `07-lifecycle.js` and
   `08-pomodoro.js`.
