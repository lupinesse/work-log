## Priorities for this week

1. **Fix `docs/` gitignore conflict** — `.gitignore` contains a bare `docs/` rule that silently prevents `git add docs/qa-reports/` from staging the weekly QA reports generated by `weekly-qa-review.yml`. Add a `!docs/qa-reports/` negation rule immediately or the automated workflow will never commit its output.

2. **Bump version and create missing git tags** — `package.json` is pinned at `1.8.0` but CHANGELOG documents four released versions (`v1.8.1`–`v1.8.4`). None of `v1.8.1`–`v1.8.4` have git tags. Run `npm version patch` for each increment, create the tags, and push. The `release.yml` workflow depends on tags to publish GitHub Releases.

3. **Update stale documentation** — `ARCHITECTURE.md` says "15 JS source modules" and its module map stops at `15-notion.js`; the codebase now has 23 modules (`16-rapid` through `23-sprints`). `QA.md` quotes "110 tests" / "160+ Playwright tests" — the correct figures are 133 unit + 211 smoke = 344. Update both files; the design certificate in `ARCHITECTURE.md` should also be re-dated.

4. **Complete JSDoc on BuJo modules** — `22-trackers.js` has 9 exported functions but only 4 JSDoc blocks; `19-monthlylog.js` has 2 of 5 functions documented; `23-sprints.js` has `/**` comments but no `@param` or `@returns` tags on any function. Running `npm run docs` currently omits or produces incomplete pages for all BuJo modules. Add full JSDoc to all eight BuJo modules (16–23).

5. **Resolve Node version inconsistency** — `.nvmrc` specifies `24.15.0`, CI workflows (`ci.yml`, `docs.yml`, `lighthouse.yml`, `release.yml`) use `node-version: '20'`, and `package.json` engines says `">=18.0.0"`. Pick one version and align all three sources; use the exact pinned version in CI rather than a major-version float.
