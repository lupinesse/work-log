   least the eighth consecutive review.** Both still read 698 unit / 320 smoke / 324 CI-script =
   1,342 total; actual today is **819 unit / 323 smoke / 372 CI-script = 1,514 total** — a 172-test,
   13% gap. The recommendation to fold this refresh into the release-cut or PR-merge checklist
   (made in every review since 2026-08-03) has still not been adopted.

4. **A second confirmed instance of "own review says `REQUEST CHANGES`, merges anyway, finding
   never fixed."** PR #385's recorded review flagged a 🔴 blocking issue: `tidyStaleEpics()`'s
   `confirm()` dialog (`src/js/02-utils.js` line 62) tells the user they can restore an archived
   epic "from ⚙ → archived" — a control this same PR deleted, replacing it with the `🗂 epics`
   toolbar button. The PR merged 58 minutes later with no follow-up commit, and **the exact stale

   serious self-flagged blocking finding (a session-id collision) *was* fixed with a follow-up
   commit before merge — the process can and does work, it just isn't consistently gated. Concretely:
   the `merge-gate` job checks that all *ChatGPT* threads are resolved, but nothing blocks a merge
   on Claude's own `REQUEST CHANGES` verdict from the same review dialogue. Fix the string (one
   line: point users at "🗂 epics" instead of "⚙ → archived"), and consider whether the merge gate
   should account for Claude's own blocking findings, not only ChatGPT's.

   built specifically to stop it.** `grep -rPo '\([a-z]\) =>' src/js/'` now counts **297**, up from

   Worth revisiting whether this needs to be `'error'` for new code, now that the tooling exists.
