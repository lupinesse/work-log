# Changelog

## Unreleased

### Changed
- **CI scripts: `github-threads.mjs` error messages are now uniform and include the function name (#588)** — all eleven throw sites in `.github/scripts/lib/github-threads.mjs` now use the pattern `<functionName> HTTP <status>: <body>` and `<functionName> GraphQL errors: <json>`, so every failure in a CI job log names the exact operation that failed without needing to consult the source file.

### Fixed
- **Time-block, emoji-picker and meeting buttons now say which block or meeting they act on (#598)** — the `×` delete, `✦` emoji and `▶ start` buttons on planned blocks, the emoji options, and the `▶ start` / `✕` buttons in the meeting strip were announced identically on every row (WCAG 4.1.2 / 2.4.6). Each now has an `aria-label` that includes the block or meeting text (e.g. "Delete block: Write report", "Select 😀"). The button markup moved into `buildBlockActionButtonsHtml()`, `createEmojiOptionButton()` and `buildMeetingButtonsHtml()` so it is unit-tested.
- **Monthly calendar derives its own `YYYY-MM` prefix (#587 follow-up)** — `buildMonthlyCalendarHtml()` and `renderMonthlyCalendar()` took `monthPrefix` as a parameter even though it is a pure function of `year` and `month`, so a caller could pass a prefix that disagreed with them. Both now compute it through a new `mlMonthPrefix()`, which `renderMonthlyLog()` also uses for the summary and task panels. No behaviour change. 1 test in `test/unit/monthlylog-calendar.test.mjs`.
- **Focus-ring rules for `.cp-add-input`, `.plan-status`, and `.emoji-picker-input` now use the shared `focus-ring` mixin** — PR #582 added three hand-written `:focus-visible` rings after the `focus-ring` mixin from #577 was not yet on main. Now that #577 is merged, the three rules are replaced with `@include mixins.focus-ring;` in `_checkpoints.scss`, `_tasks.scss`, and `_picker.scss`. No visual change.
- **`markInputInvalid()` no longer stacks listeners on repeated rejection** — calling `markInputInvalid()` on the same input twice before the user edits added a second `{ once: true }` listener, which would fire on the next edit and attempt a spurious DOM update. A module-level `WeakSet` now tracks inputs with a pending listener; a new call skips `addEventListener` if one is already registered and re-registers once the user edits. 2 new tests in `test/unit/utils-categories.test.mjs`.
- **Dark-mode `--color-error` token moved next to the other validation tokens in `_base.scss`** — it sat between `--live` and `--live-deep`, splitting the related live-colour group. It now follows `--live-softer` where all error/danger tokens begin.
- **Gap-report jsdom test now loads `trapFocusInOverlay` and fails when an event handler throws (#602)** — `gapreport-dom.test.mjs` evaluated `12c-gapreport.js` without `focus-utils.js` (extraction #17), so its Tab test logged `ReferenceError: trapFocusInOverlay is not defined` yet passed. The shipped app was never affected: `script.js` imports the helper from `focus-utils.js`. The test now loads it, gains a Tab-wrap regression test, and `createDom()` in `test/unit/_helpers.mjs` collects errors jsdom would only log, exposed via the new `assertNoUncaughtErrors()` and asserted in that file's `afterEach`. The new Tab test fails on the previous harness.
- **Every jsdom test now fails when an event handler throws (#610)** — #605 added `assertNoUncaughtErrors()` but only `gapreport-dom.test.mjs` called it, so the other `createDom()` callers could still pass while a handler threw. `a11y-keyboard-focus`, `adhoc-row`, `calendar-strip`, `eod-copy-button`, `focus-trap-dom`, `monthlylog-calendar`, `monthlylog` and `quickpick-dom` now assert it (in `afterEach`, or per test), including the extra DOMs mounted inside tests. None of them surfaced a hidden error. Test-only change.
- **Monthly calendar day cells are now keyboard-operable and nav buttons have accessible names (#587)** — day cells were `<div>` elements, so keyboard users could not reach or activate them (WCAG 2.1.1 Keyboard). The prev/next navigation buttons had no accessible name, giving screen-reader users no indication of where they would navigate (WCAG 4.1.2 Name, Role, Value). Day cells are now `<button type="button">` elements with `aria-label` attributes including the date and logged hours; empty grid-spacer divs gain `aria-hidden="true"`; nav buttons carry `aria-label="Previous/Next month: <name>"` naming the target month. CSS resets and `:focus-visible` outlines added for `.ml-cell` and `.ml-nav-btn`. 8 unit tests in `test/unit/monthlylog.test.mjs` cover button element type, `aria-label` content, click behaviour, and year-boundary month wrapping.
- **The pomodoro completion tick follows the theme (#511)** — `.pomo-checkmark` hard-coded `#16a34a` with no dark value. It now uses a new `--color-success` token (`#16a34a` light, `#4ade80` dark). Also renames `_pomoFaviconEl` to `pomoFaviconEl` and `cs` to `rootStyle` in `08-pomodoro.js`. 2 tests in `test/unit/design-tokens-css.test.mjs` compile the real stylesheet and fail on the old SCSS.
- **Zero-length stopped sessions show `00:00` in the hero card (#488)** — `_heroFillStopped()` hard-coded `0:00` while every other hero clock formats through `fmtElapsed()` (`00:00`); it now calls `fmtElapsed()` for all durations. Also replaces the four independent `if (state === …)` fill blocks in `renderHeroCard()` with a `switch` (#486). Tests in `test/unit/hero.test.mjs`.
- **Calendar debug payload reports `pass1Error`/`pass2Error` as arrays (#517)** — `start-server.ps1` built these by string `+=` with a hand-added `"; "`, so several failures ran together into one string in the JSON debug payload. Each error is now its own array element (`[]` when none), in `start-server.ps1` and `server-helpers.ps1`, and the Pester mock and assertion follow. Nothing in `src/js` reads these fields. Verified by running the real `Add-RecurringOccurrence` failure path under PowerShell 7 (one element recorded, no throw, JSON serialises as an array); the Pester suite itself could not be run in this environment.
- **OpenAI review scripts read `MAX_COMPLETION_TOKENS` instead of `MAX_TOKENS` (#502)** — the cap feeds OpenAI's `max_completion_tokens`, so the old name was misleading. `chatgpt-review.mjs` and `chatgpt-claude-dialogue.mjs` now call a shared `readMaxCompletionTokens()` (`.github/scripts/lib/max-completion-tokens.mjs`): it prefers the new variable, still honours `MAX_TOKENS` for one release with a deprecation warning, and throws a clear error for a non-numeric or non-positive value instead of sending `NaN` to the API. `chatgpt-pr-review.yml` now sets the new name. The Anthropic scripts keep `MAX_TOKENS`, which matches their API's `max_tokens`. 9 tests in `.github/scripts/test/max-completion-tokens.test.mjs`.
- **EOD copy button no longer sticks on "Copied!" after a double click (#545)** — the handler read the button's current markup as the label to restore, so a second click during the 2s flash saved "Copied!" as the original. The label is now remembered once per button in `flashCopiedLabel()` (`12a-changelog.js`). 2 tests in `test/unit/eod-copy-button.test.mjs`; the double-click case fails on the previous logic.
- **Rejected epic names get a theme-aware error border that clears on edit (#524)** — four call sites set `input.style.borderColor = '#C62828'` and never reset it, so the input stayed red after the user corrected the name, and the colour ignored dark mode. They now call one shared `markInputInvalid()` (`02-utils.js`), which adds an `input--invalid` class (new `--color-error` token with a dark value in `_base.scss`), sets `aria-invalid`, focuses the input and removes both on the next edit. 2 tests in `test/unit/utils-categories.test.mjs`.
- **Emoji no longer pollute accessible names or the timesheet live region (#545)** — the End of Day timesheet status (`setTimesheetStatus`, an `aria-live` region) wrote `✅`/`⚠`/`⏳` into its messages, and the copy/submit buttons began with an emoji that screen readers read aloud. Status messages are now plain text (the existing error modifier class still carries the visual distinction), and the button emoji sit in `aria-hidden` spans; the EOD copy button restores its markup after the "Copied!" flash instead of overwriting it with text. 1 regression test in `test/unit/gofore-timesheet-client.test.mjs`.
- **Inline text inputs now show a visible keyboard-focus ring (#513)** — `.cp-edit-input`, `.plan-inline-input`, `.cat-inline-input` and `.pcat-add-input` set `outline: none` with no replacement, so keyboard users could not see where focus was (WCAG 2.4.7, 1.4.11). Each now has a `:focus-visible` rule using a new shared `focus-ring` mixin (`src/css/_mixins.scss`), matching the ring on `.date-nav-location`. 4 regression tests in `test/unit/focus-ring-css.test.mjs` compile the real stylesheet and fail on the pre-fix SCSS.
- **Jira ticket links now tell screen-reader users they open in a new tab (#471)** — `jiraTicketHtml()` and the sub-stat tiles rendered `target="_blank"` links with no warning (WCAG 3.2.2 / 2.4.4). Both now build the link through one shared `jiraKeyLinkHtml()` in `pure-fns-format.js`, which appends a visually hidden `(opens in new tab)` suffix using the existing `.sr-only` class; there is no visible change. 4 unit tests in `test/unit/pure-fns-format.test.mjs`.
- **Analytics, parked-thoughts and Pomodoro headers, and three inputs, are now usable by keyboard (WCAG 2.1.1, 2.4.7)** — `#analyticsHeader`, `#parkHeader` and `#pomoHeader` are `role="button"` with `tabindex="0"` but had only click listeners, so Enter/Space did nothing; they now join the other six headers in `KEYBOARD_ACTIVATED_HEADER_IDS` (`12-misc.js`). `.cp-add-input`, `.plan-status` and `.emoji-picker-input` set `outline: none` with no replacement, so focus was invisible; each now has a `:focus-visible` ring matching `.date-nav-location`. 9 tests in `test/unit/a11y-keyboard-focus.test.mjs` check the header list against `work-log.html` and compile the real stylesheet; the five regression cases fail on the previous code.
- **Focus trap no longer treats `tabindex="-1"` controls as the first/last focusable element (#556)** — `trapFocusInOverlay` (in `02-utils.js` and the private copy in `12d-weeklyreport.js`) matched `button:not([disabled])`, `input`, `a[href]` etc. regardless of `tabindex`, so an untabbable control at either edge of an overlay became the trap's edge and Tab/Shift-Tab could leave the dialog (WCAG 2.1.2). Candidates are now also filtered on `tabIndex >= 0`. Latent: no shipped overlay has such a control today. 6 regression tests in `test/unit/focus-trap-dom.test.mjs` (button, input and link at both edges, across both copies) fail on the pre-fix code.
- **ChatGPT review workflow identifies its bot by exact login, not a `chatgpt` substring (#514)** — `chatgpt-pr-review.yml` used `.includes('chatgpt')` in two places: the synchronize "already reviewed" guard and the `merge-gate` unresolved-thread check. Any human handle containing `chatgpt` (a contributor, a fork, a different bot) was treated as the review bot, so a PR that only a human had commented on would skip its first review, and a human's unresolved thread would block the merge gate. Both checks now compare by equality against one `CHATGPT_REVIEW_BOT_LOGIN` defined once in the workflow-level `env:` (`chatgpt-reviewer-work-log[bot]`, confirmed against the logins on this repo's existing PR comments). GraphQL reports the same bot as `chatgpt-reviewer-work-log` without the `[bot]` suffix, so `merge-gate` strips it before comparing — a naive shared constant would have made the gate silently pass. A missing variable throws rather than matching nothing. 11 tests in `.github/scripts/test/chatgpt-bot-login.test.mjs` run the real inline scripts against fake API data; 7 fail on the pre-fix workflow.
- **Focus trap added to weekly-report and gap-report overlays (WCAG 2.1.2)** — pressing Tab/Shift-Tab while either overlay is open now cycles only within that dialog; focus can no longer escape to background content. Implemented via a shared `trapFocusInOverlay()` utility in `02-utils.js`, wired into the `keydown` listeners of `12c-gapreport.js` and `12d-weeklyreport.js`. The three ARIA attributes that were also flagged in the a11y audit (`role="dialog"`, `aria-modal="true"`, `aria-labelledby`, and `aria-live="polite"` on the copy-feedback element) were already present in `work-log.html`.

### Security
- **GitHub Actions in all workflows pinned to commit SHAs (#503)** — every workflow used floating tags (`checkout@v7`, `setup-node@v7`, `github-script@v9`, `create-github-app-token@v3`, `upload-artifact@v7`, `actions-gh-pages@v4`, `lighthouse-ci-action@v12`, `codeql-action@v4`), which can be re-pointed without review. Each is now pinned to the full-length SHA the tag resolved to (annotated tags peeled to their commit), with a `# vX.Y.Z` comment so Dependabot's existing `github-actions` ecosystem entry keeps proposing bumps. No behaviour change. `peaceiris/actions-gh-pages` and `github/codeql-action` have no release tag at the commit their `v4` tag points to, so those are pinned to that commit with a `# v4` comment rather than moved to a different release. A test in `.github/scripts/test/workflow-action-pins.test.mjs` checks every `.yml` in `.github/workflows/` and fails on the pre-change workflows.
- **`POST /api/gofore-timesheet` can no longer be triggered while submission is disabled or from another website (#476)** — `GOFORE_SUBMIT_ENABLED` only hid the button, and the server answered every response with `Access-Control-Allow-Origin: *`, so any page open in the browser could POST to `localhost:8080` and drive the user's signed-in Chrome/Playwright session. The route now consults a new pure `Get-GoforeRequestDecision` (`server-helpers.ps1`) before running anything: it returns 403 unless `$GoforeSubmitEnabled` in `config.local.ps1` is a real `$true` (default `$false`; a quoted `'false'` is also refused), and 403 when the `Origin` is not the server's own local origin or the `Host` is not a local name (DNS-rebinding). The wildcard CORS header is removed from `start-server.ps1` altogether — the app is served same-origin, so nothing needed it. The startup `[cfg]` line reports whether the endpoint is enabled and each refusal is logged with its reason. `config.local.example.ps1` documents the setting; README security model updated. 30 Pester tests in `test/gofore-guard.Tests.ps1`, including the rejected-origin table, the rebinding case, check order, and that `start-server.ps1` has no wildcard CORS and calls the guard before `Invoke-GoforeTimesheet`. **Upgrade note:** to keep using one-click submit, add `$GoforeSubmitEnabled = $true` to your `config.local.ps1`.

- **`npm run session:*` — a guard that makes another session's working-tree changes visible instead of silent (#268)** — this checkout is driven by several concurrent Claude Code sessions and tools, and git records *what* changed in a working tree but never *who* changed it. #268 recorded the consequence: a session whose own `git status` had been clean mid-session found a **staged** edit to `.github/workflows/a11y-audit.yml` that it had never made, after running only read-only commands. Nothing was lost that time, but the same surprise arriving one command later — `git checkout --`, `git reset --hard`, `git stash` — would have destroyed another session's in-progress work with no trace of where it went. `npm run session:claim` records a baseline (branch, HEAD, and every dirty path); `npm run session:check` diffs the tree against it and names the other sessions currently registered on the checkout, exiting `1` when anything moved so it can gate a script; `--accept` re-baselines once the drift has been reviewed; `session:list` and `session:release` round out the set. Where two sessions share one directory — the #268 condition exactly — the report says so outright rather than leaving it to be inferred from an unexplained diff. Locks are JSON files under the git *common* directory (`.git/worklog-session-locks/`), not inside a working tree, because linked worktrees do not share each other's files but do share `.git` — that is what makes one session's lock visible to another. Liveness is judged by age (8 h, `--ttl-hours=N` to override) rather than by process id, since every invocation is a short-lived `npm run` process whose pid says nothing about whether the session behind it is still working. The guard only ever reports: it never writes to the working tree and cannot stop another process from writing, so the convention it supports — one git worktree per session — is documented alongside it in `CONTRIBUTING.md` and as Step 0 of the `CLAUDE.md` PR workflow. Logic in `scripts/lib/session-guard.mjs` with `scripts/session-guard.mjs` as a thin entry point, covered by 83 tests. 65 unit tests (`test/unit/session-guard.test.mjs`) cover the logic — the #268 scenario itself as a regression fixture (clean baseline, foreign staged workflow file appears, drift reported), porcelain parsing of renames and C-quoted non-ASCII paths, TTL expiry, corrupt lock files, and session-id sanitising that keeps a lock file inside its own directory. 18 end-to-end tests (`test/unit/session-guard-cli.test.mjs`) drive the real CLI against a throwaway `git init` repository, because verb dispatch, the 0/1/2 exit codes, and where the lock lands relative to the git common directory only exist once git is involved: claim → foreign file appears → check exits 1 → `--accept` → clean, plus HEAD moving under the session, two sessions in one directory, a corrupt lock, and running outside a repository at all. A second `claim` under an identifier that already holds the checkout is refused rather than silently re-baselined — a review caught the guard reproducing #268 inside itself: two sessions in one directory derive the same default identifier, so B's claim would fold A's uncommitted file into B's baseline and the next check would call the tree clean. No derived identifier can avoid that, since anything stable enough to find the same lock on the next invocation is shared by whoever else is in that directory, so uniqueness has to be stated: the refusal names both remedies (`--accept` to re-baseline deliberately, `--session=ID` to register separately). Drift is measured at `git status` granularity, so a file already `M` in the baseline that is modified again is not reported — documented as a known limit in the module docstring and `CONTRIBUTING.md` rather than papered over, since `git status --porcelain` collapses untracked directories to one entry that cannot be hashed without walking it. The session identifier is never read from the environment: it is printed in every report, and CodeQL rightly declines to tell a session *label* from a session *token* when both would arrive through a `*_SESSION_ID` variable — `--session=ID` says the same thing without routing anything from the environment to a log line, and the default (host plus worktree directory name) is stable across invocations in a way a process id is not. `--ttl-hours` is floored at 30 minutes, since pruning deletes *other* sessions' baselines and a guard against destroying another session's state must not become the thing that does it because of a mistyped flag; a check against a baseline older than the TTL says so before listing drift, because at that age the age is the finding rather than the paths.

Extracted to a single exported `postInlineComment()` in the shared lib (matching the JSDoc style of `replyToThread`), updated both callers to import it, and removed the now-unused `GH_HEADERS` constant from `chatgpt-claude-dialogue.mjs`. A regression test (`github-threads.test.mjs`) asserts the header is present — the test fails against the old private implementation. `format` and `format:check` scripts extended to cover `.github/scripts/**/*.mjs` alongside the existing `lint` coverage.
- **Blank thread indices in AI dialogue responses are no longer misrouted to thread 0.** Both `chatgpt-review.mjs` (Phase 1 reply actions) and `claude-chatgpt-dialogue.mjs` (Phase 2 thread responses) coerced the model-supplied index with bare `Number(…)`, but `Number('')` and `Number('   ')` evaluate to `0` — so a malformed response carrying a blank `thread_index`/`index` would silently post a reply to thread 0 instead of being rejected to the fallback bucket. The trim-and-reject guard already used by `normaliseReplyAction` is extracted into a shared, unit-tested `coerceThreadIndex()` helper in `lib/parse-reply-action.mjs` and applied at both call sites. Covered by 9 new unit tests.
- **ESLint and Prettier now cover the CI dialogue scripts (`.github/scripts/**/*.mjs`).** `npm run lint` previously only scanned `src/js/`, `*.js`, and `*.cjs`, so these files were never linted. A new flat-config block lints them as Node ES modules, the `lint` script glob now includes them, and `format`/`format:check`/`lint-staged` are extended to match.
- **Phase 2 dialogue (`claude-chatgpt-dialogue.mjs`) no longer hard-fails when `CLAUDE_CODE_OAUTH_TOKEN` is absent, expired, or rate-limited.** The `claude-responds` job previously failed immediately in those cases, leaving ChatGPT's review threads un-triaged and blocking the merge-gate. Credentials now form an ordered chain (`resolveAnthropicAuthChain()` in `lib/anthropic-auth.mjs`): the request tries the OAuth token first and, on a `401`/`403` (rejected) or `429` (rate-limited), automatically falls through to `ANTHROPIC_API_KEY` via `shouldFallThrough()` — so an expired-but-present token or a momentarily exhausted quota is recovered without failing the job. The model defaults per auth source via `selectModel()`: Opus on the flat-rate OAuth path, Haiku on the metered API-key path (a `MODEL` env var overrides either); an unrecognised source defaults to Haiku (cost-safe). Covered by 20 unit tests in `test/anthropic-auth.test.mjs`.
- **Review workflows no longer post a spurious "neither secret is set" skip notice on large PRs.** Both `pr-review.yml` and `chatgpt-pr-review.yml` gated their "mint app token" and "post review comment" steps on `steps.key-check.result != 'skipped'`, but a step context exposes `conclusion`/`outcome`, *not* `result` — so the expression was always truthy and the post step ran even when the auth check had been skipped (e.g. on a large PR, where `pr-review.yml` deliberately hands the review to the dialogue pipeline). The result was a misleading comment claiming no Anthropic credential was configured, regardless of whether one was. Corrected to `steps.key-check.conclusion != 'skipped'` in all four step guards.
- **Phase 4 dialogue (`chatgpt-claude-dialogue.mjs`) now finds Claude's comments on high-volume PRs.** `fetchClaudeIssueComments()` previously fetched only the first 100 issue comments (`?per_page=100` with no pagination), so Claude's synthesis and final verdict were invisible on PRs with ≥ 101 comments. A new `fetchAllIssueComments()` helper in `lib/github-threads.mjs` paginates until the API returns a partial page, and both `fetchClaudeIssueComments()` and `upsertIssueComment()` now use it. The `/pr-review` string fallback (which could false-positive on bare user-invocation comments) is replaced with `claude.ai/claude-code`, a string that only appears in Claude-generated attribution footers.
- **Phase 4 prompt now scans threads, verifies fix claims, and posts an explicit audit trail.** The Phase 4 system prompt now: (a) instructs ChatGPT to scan both resolved and open threads before choosing any action; (b) requires ChatGPT to locate Claude's promised fix in the diff at the relevant file/line before trusting any `✅ agree_fix` reply (or synthesis / `/pr-review` claim like "now fixed in commit X"); (c) on confirmed fixes, ChatGPT posts a reply starting with `✅ Verified as fixed` and sets `resolve: true` so the thread closes and the merge-gate clears; (d) on regressions (fix promised earlier but no longer in the diff), ChatGPT posts a reply starting with `🔁 Reopened —` and sets `unresolve: true`; (e) when a prior run already posted "Verified as fixed" and nothing has changed, ChatGPT omits — confirmations are idempotent; (f) anchors verdict selection so APPROVE is chosen when nothing genuinely novel remains, REQUEST_CHANGES only for novel blocking concerns or blocking regressions. The `resolve` / `unresolve` flag mechanism shipped in the previous commit; this commit teaches the model when to emit each.
- Malformed Outlook calendar meeting objects (e.g. missing `subject`, `start`, or `end`) are now filtered out before rendering rather than appearing as `"undefined"` in the meeting strip
- Weather API responses with an unexpected shape now fall back to showing the city name (same as a network error) instead of leaving the weather widget empty
- Jira CSV files with a wrong delimiter (e.g. semicolons) now log a console warning and show the "No tasks found" message rather than silently dropping all rows
- Jira invalid-row warning now logs the full list of malformed rows instead of only the first row, so all problem rows are visible in a single DevTools entry
- **`chatgpt-pr-review.yml` now posts reviews reliably.** Replaced `anc95/ChatGPT-CodeReview@main` (Node.js 20 — deprecated June 2026, silently exited without calling the API) with a direct OpenAI `chat/completions` call. The review logic now lives in a standalone `.github/scripts/chatgpt-review.mjs` (native `fetch`, no external deps) rather than inline YAML, so it's readable and testable.
